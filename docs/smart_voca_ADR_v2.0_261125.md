## ADR-006: 기존 퀴즈(`vocab-quiz/`)를 새 웹 앱으로 대체

- **상태**: 승인 (2026-11-25)
- **배경**: 요건 v1.1은 웹 앱, DB 이력, 암기·시험·통계, 도전 기능(로그인 등)을 요구한다. 기존 퀴즈는 정적 파일이고 DB가 없다.
- **대안**
  1. 기존 퀴즈에 서버와 DB를 덧붙인다
  2. 새 웹 앱을 `app/`에 만들고 기존 퀴즈는 제거한다 (선택)
- **결정 근거**: 기존 퀴즈의 로직(재출제, 오답 선택지)은 새 요건의 시험 기능과 규칙이 다르다. 새로 만드는 편이 추적성(FR ID)을 맞추기 쉽다.
- **결과**: `vocab-quiz/`는 삭제한다. 이력은 git 커밋에 남는다.

## ADR-007: 서버와 DB를 Node.js 내장 모듈로 구현 (외부 패키지 0개)

- **상태**: 승인 (2026-11-25, 구현 방식은 작성자 판단)
- **배경**: 요건은 DB(SQLite)와 웹 서버를 요구한다. 학교 서버에서 설치 없이 실행되어야 한다 (VOCA-SUB-036).
- **대안**
  1. Express + better-sqlite3 (npm 설치, better-sqlite3는 네이티브 빌드 필요)
  2. Python Flask + sqlite3
  3. Node.js 내장 `node:http` + `node:sqlite` (선택)
- **결정 근거**
  - Node 24에 `node:sqlite`가 내장되어 있다 (SQLite 3.50). `npm install` 없이 `node:test`와 같은 방식으로 실행된다.
  - 프레임워크 없이 라우팅 수십 개 정도는 다루기 충분하다.
  - Docker 이미지에 `npm ci` 단계가 없어 빌드가 단순하다.
- **결과와 제약**
  - `node:sqlite`는 실험 기능이라 실행 시 경고가 출력된다. Node 버전을 24로 고정한다.
  - 프레임워크 미사용으로 라우터와 본문 파싱을 직접 작성한다 (`app/server/`).

## ADR-008: 단어 등록과 복습 규칙

- **상태**: 승인 (2026-11-25)
- **배경**: CSV 중복 처리(요건 VOCA-FR-003)와 복습 섞기(VOCA-FR-013), 출제 가중치(VOCA-FR-022)를 정해야 한다.
- **결정**
  1. **중복 처리**: 영단어를 소문자와 공백 제거 기준으로 같은 단어로 본다. 같은 단어는 한 행으로 저장하고, 뜻이 다르면 `;`로 합친다. 같은 뜻은 한 번만 넣는다. 가져오기 결과에 추가·갱신·건너뜀 건수를 보여준다.
  2. **암기 진도**: 하루 학습량 N개씩 `day` 번호를 매긴다. 기본 N은 20이다 (설정에서 변경).
  3. **복습 섞기**: 오늘 암기 목록의 `복습 비율`(기본 30%)만큼, 직전 일차 단어와 자주 틀린 단어에서 채운다. 후보가 모자라면 이미 외운 다른 단어로 채운다.
  4. **시험 가중치**: 미출제 단어 가중치 3, 오답 이력이 있는 단어 가중치 2, 그 밖에는 1로 두고 가중치 비례 무작위 추출을 한다. 중복 출제는 한 시험 안에서 하지 않는다.

## ADR-009: 시험 형식은 단답형과 4지선다

- **상태**: 승인 (2026-11-25)
- **배경**: VOCA-FR-024는 2가지 이상 형식을 요구한다.
- **결정**: 단답형(입력 후 정답 비교, 대소문자 무시)과 4지선다(오답 3개는 같은 일차 또는 전체 단어에서 뜻이 다른 단어로 뽑음)를 구현한다. OX는 도전 범위에서 추후 추가한다.
- **방향**: 영→한, 한→영, 섞기를 지원한다 (VOCA-FR-023).

## ADR-010: 로그인은 세션 쿠키와 scrypt 해시

- **상태**: 승인 (2026-11-25, 구현 방식은 작성자 판단)
- **배경**: 도전 기능 로그인(VOCA-FR-041~043)과 비밀번호 해시(VOCA-FR-042)가 필요하다.
- **결정**
  - 비밀번호는 `node:crypto`의 `scrypt`와 무작위 salt로 해시하여 저장한다.
  - 로그인 시 무작위 세션 토큰을 발급하고 `HttpOnly` 쿠키로 보낸다. 세션은 DB `sessions` 테이블에 저장한다.
  - 세션 키는 환경변수 `SECRET_KEY`로 받는다 (VOCA-NFR-004). 없으면 서버 시작 때 무작위로 만든다. 재시작하면 로그인이 풀린다.
  - DB `sessions` 테이블에는 세션 토큰 자체가 아니라 `SECRET_KEY`로 만든 HMAC-SHA256 값만 저장한다. DB가 새도 쿠키를 만들 수 없다.
- **정정 (2026-11-25)**: 초안의 "세션 토큰은 무작위라 비밀 키가 필요 없다"는 문구를 위 내용으로 바꿨다. 구현은 `SECRET_KEY`와 HMAC 저장을 따른다.

## ADR-011: Docker 이미지와 SQLite 경로

- **상태**: 승인 (2026-11-25, 정정 반영). 조건 원문은 `ai-agent/uploads/04_Dockerfile 프롬프트.md`
- **결정**
  - 베이스 이미지 `node:24.11.0-slim` (버전 고정, slim 계열, latest 금지). 실행 사용자 UID 10001, 포트 8080.
  - DB 경로는 환경변수 `DB_PATH`로 받고 기본값은 `/data/voca.db`로 둔다. `/data` 소유자는 10001.
  - 쓰기는 `/data`와 `/tmp`에만 한다.
- **정정 (2026-11-25)**: 초안의 `node:24-alpine`을 `node:24.11.0-slim`으로 바꿨다. 규칙 조건 1(slim, 버전 태그)에 맞추기 위해서다. 「Dockerfile 구성」의 R-01~R-10은 `04_Dockerfile 프롬프트.md`의 조건 1~9로 대조했다.
- **미확인 사항**: `.github/workflows/docker-check.yml`은 `ai-agent/uploads/`에 없다. 학교 파일을 리포에 직접 넣어야 한다. `cap-drop ALL`은 서버 실행 옵션이다.
- **앱 주소**: 서버가 `/2026/voca-<학번>/` 아래로 옮겨 주므로 앱은 상대 경로만 쓴다 (VOCA-SUB-033).
