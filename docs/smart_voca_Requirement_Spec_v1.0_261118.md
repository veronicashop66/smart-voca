## 1. 목적 및 기준

- 기준 문서: `docs/smart_voca_Project_Charter_v1.0_261118.md` (목표 G-1~G-4, 범위 4장, 재출제 규칙 4.3)
- 상태 구분
  - **구현됨**: 현재 `vocab-quiz/`에 코드가 있음
  - **미구현**: 기획에는 있으나 코드가 없음
- ID 규칙: 기능은 `FR-번호`, 비기능은 `NFR-번호`. 번호는 한 번 부여하면 바꾸지 않는다.

## 2. 기능 요구사항 (FR)

### 2.1 단어 데이터

| ID | 요구사항 | 상태 | 목표 |
| :--- | :--- | :---: | :---: |
| FR-01 | 시스템은 수능 빈출 단어 64개와 각 단어의 뜻·예문을 로드한다. | 구현됨 | G-1 |
| FR-02 | 시스템은 단어 데이터를 시작 시 검증한다. 예문 2개 미만, 뜻 중복, 오답 후보 부족(선택지 수 대비)이면 오류를 낸다. | 구현됨 | G-1 |
| FR-03 | 한 단어의 뜻은 쉼표로 구분된 여러 뜻을 가질 수 있으며, 개수 제한은 없다. | 구현됨 | G-1 |

### 2.2 문제 출제

| ID | 요구사항 | 상태 | 목표 |
| :--- | :--- | :---: | :---: |
| FR-04 | 모든 단어는 신규 출제 순서가 무작위인 상태로, 처음에 한 번씩 출제된다. | 구현됨 | G-1 |
| FR-05 | 문제는 단어가 포함된 예문 1개를 먼저 보여주고, 그 단어의 뜻을 4지선다로 고르게 한다. | 구현됨 | G-1 |
| FR-06 | 예문 속 단어(굴절형 포함)에 밑줄을 긋는다. 현재는 굵은 글씨로 표시하므로 밑줄로 바꾼다. | 구현됨 (변경 필요) | G-1 |
| FR-07 | 선택지는 정답 1개와 오답 3개로 구성하며, 오답은 다른 단어의 뜻 중 정답과 뜻을 하나라도 공유하지 않는 것에서 고른다. | 구현됨 | G-1 |
| FR-08 | 같은 단어를 낼 때 이전에 보여준 예문은 피한다. 예문을 모두 보여줬다면 직전 예문만 피한다. | 구현됨 | G-2 |

### 2.3 정답 판정과 피드백

| ID | 요구사항 | 상태 | 목표 |
| :--- | :--- | :---: | :---: |
| FR-09 | 사용자가 보기를 고르면 정답 여부를 즉시 판정한다. 정답 보기는 초록색, 틀린 선택은 빨간색으로 표시한다. | 구현됨 | G-1 |
| FR-10 | 정답 후 단어의 뜻 전체(여러 뜻)를 함께 보여준다. | 구현됨 | G-1 |
| FR-11 | 정답 후 "다음" 버튼이 나타나고, 세션이 끝나는 문제면 "결과 보기"로 표시한다. | 구현됨 | G-1 |

### 2.4 틀린 단어 재출제

| ID | 요구사항 | 상태 | 목표 |
| :--- | :--- | :---: | :---: |
| FR-12 | 틀린 단어는 재출제 대기 목록에 넣는다. | 구현됨 | G-2 |
| FR-13 | 재출제는 틀린 문제 이후 **최소 8문제** 뒤부터 가능하며, 그 뒤 **0~4문제** 사이에서 무작위로 정한 시점에 출제한다. 즉 8~12문제 뒤에 출제된다. | 구현됨 | G-2 |
| FR-14 | 재출제 시점이 된 항목이 여러 개면 그중 하나를 무작위로 고른다. | 구현됨 | G-2 |
| FR-15 | 재출제 문제는 "다시 풀기"로 표시한다. 신규 문제는 "새 단어"로 표시한다. | 구현됨 | G-2 |
| FR-16 | 재출제는 맞힐 때까지 반복한다. | 구현됨 | G-2 |
| FR-17 | 신규 단어가 모두 나간 뒤 재출제 대기만 남았으면, 8문제 간격을 채우지 못하더라도 가장 먼저 예정된 단어를 낸다. | 구현됨 | G-2 |

> 우선순위: 재출제 시점이 된 항목을 신규 단어보다 먼저 낸다. (Q-1 결정: 현재 방식 유지)

### 2.5 세션 진행과 종료

| ID | 요구사항 | 상태 | 목표 |
| :--- | :--- | :---: | :---: |
| FR-18 | 화면 상단에 현재 문제 번호, 남은 신규 단어 수, 재출제 대기 수를 표시한다. | 구현됨 | G-1 |
| FR-19 | 신규 단어와 재출제 대기가 모두 없으면 세션을 끝내고 결과를 보여준다. | 구현됨 | G-1 |
| FR-20 | 결과 화면에는 총 단어 수, 총 답변 수, 첫 시도 정답 수를 표시한다. | 구현됨 | G-1 |
| FR-21 | "다시 시작" 버튼으로 새 세션을 시작한다. | 구현됨 | G-1 |

### 2.6 학습 기록 (브라우저 저장)

| ID | 요구사항 | 상태 | 목표 |
| :--- | :--- | :---: | :---: |
| FR-22 | 단어별 누적 정답 횟수와 오답 횟수를 브라우저 localStorage에 저장한다. 매 답변 후 갱신한다. | 미구현 | G-3 |
| FR-23 | 진행 중인 세션 상태(남은 신규 단어, 재출제 대기 목록과 각 시점, 현재 문제 번호)를 localStorage에 저장한다. 매 답변 후 갱신한다. | 미구현 | G-3 |
| FR-24 | 페이지를 열면 저장된 진행 세션이 있으면 그 상태에서 이어서 출제한다. 세션 상태가 없으면 새 세션을 시작한다. | 미구현 | G-3 |
| FR-25 | 세션이 끝나면(결과 화면) 저장된 진행 세션 상태를 지운다. 누적 정답·오답 기록은 유지한다. | 미구현 | G-3 |
| FR-26 | "다시 시작" 버튼은 새 세션을 시작하고 저장된 진행 세션 상태를 덮어쓴다. | 미구현 | G-3 |
| FR-27 | 저장된 데이터가 손상되었거나 형식이 맞지 않으면 무시하고 새 세션을 시작한다. 손상 사실을 화면에 알린다. | 미구현 | G-3 |
| FR-28 | 저장 데이터에는 단어 번호와 정오 횟수, 세션 상태만 넣는다. 개인 식별 정보는 넣지 않는다. | 미구현 | G-3 |

> 세부 설계(키 이름, 저장 형식, 손상 판정)는 데이터 설계서에서 정한다.

## 4. 제외 범위 (기획서 4.2 기준)

- 단어 추가·수정·삭제 (FR 없음)
- 서버, DB, 로그인, 기기 간 동기화
- 발음(TTS), 음성 입력
- 오프라인 전용 동작(PWA)
- 정답률 상세 통계 그래프
- 다국어 UI

## 6. 결정 사항 (작성자 답변)

| ID | 질문 | 결정 |
| :--- | :--- | :--- |
| Q-1 | 재출제 시점이 된 항목과 신규 단어가 동시에 있을 때 어느 쪽을 먼저 낼까요? | 재출제 먼저 (FR-14 기준) |
| Q-2 | 학습 기록으로 무엇을 저장할까요? | 단어별 누적 정답·오답 횟수 (FR-22) |
| Q-3 | 새로고침 후 어떻게 할까요? | 진행 중이던 세션을 이어감 (FR-23~25) |
| Q-4 | 예문 속 단어 표시 방식은? | 밑줄로 변경 (FR-06) |

**작성 시 추가한 내용 (확인 필요)**
- FR-25: 세션 완료 시 진행 상태를 지우고, 누적 기록은 유지합니다. 세션을 이어갈 대상이 없어지는 시점을 정한 것입니다.
- FR-26: "다시 시작"은 저장된 진행 상태를 덮어씁니다.
- FR-27: 저장 데이터가 깨졌을 때의 처리입니다. 조용히 무시하지 않고 알리도록 했습니다.
