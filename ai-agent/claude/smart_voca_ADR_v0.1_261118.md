## ADR-001: 구현 기술로 순수 HTML·CSS·JavaScript 사용

- **상태**: 승인 대기 (2026-11-18 초안)
- **배경**: 개인용 단어 퀴즈이고 화면이 한 장이다. 설치 없이 브라우저에서 열리고, GitHub Pages로 배포해야 한다. (기획 7장, NFR-01)
- **대안**
  1. React + Vite 같은 프레임워크 빌드 구조
  2. Next.js 같은 서버 렌더링 구조
  3. 순수 HTML·CSS·JavaScript (선택)
- **결정 근거**
  - 빌드 단계가 없으므로 배포가 파일 복사로 끝난다.
  - 현재 코드가 이미 이 구조이고, 로직과 화면이 분리되어 있다.
  - 프레임워크를 도입하면 학습 대상이 아닌 도구 설정에 시간이 든다.
- **결과와 제약**: 컴포넌트 구조가 없으므로 화면 코드가 커지면 파일 분리 규칙(CLAUDE.md 5번)을 따른다. 모듈 간 연결은 전역 객체로 한다.

## ADR-002: 학습 기록을 브라우저 localStorage에 저장

- **상태**: 승인 대기 (2026-11-18 초안)
- **배경**: 기록을 남기되 서버는 두지 않는다. 기록은 본인만 본다. (기획 4장, 7장, FR-22~28)
- **대안**
  1. 서버와 DB (예: Firebase, 자체 서버)
  2. IndexedDB
  3. 파일 내보내기·가져오기 (JSON 다운로드)
  4. localStorage (선택)
- **결정 근거**
  - 데이터가 작고(수 KB), 동기 방식으로 충분하다.
  - 서버와 계정이 필요 없어서 개인정보 부담이 없다.
  - 파일 방식은 매번 수동 작업이 필요하다.
- **결과와 제약**
  - 브라우저 데이터를 지우면 기록이 사라진다. (기획 12장)
  - 기기 간 동기화는 하지 않는다.
  - 필요해지면 내보내기 기능을 별도 요구사항으로 추가한다.

## ADR-003: 배포는 GitHub Pages 정적 호스팅

- **상태**: 승인 대기 (2026-11-18 초안)
- **배경**: 정적 파일만 있으므로 무료 정적 호스팅이면 충분하다. 저장소가 GitHub에 있다. (기획 4장, NFR-02)
- **대안**
  1. Netlify, Vercel 같은 다른 정적 호스팅
  2. Docker 컨테이너와 서버 (운영/배포 정의서 방식)
  3. 로컬에서만 실행
  4. GitHub Pages (선택)
- **결정 근거**
  - 저장소와 같은 곳에서 관리하고, 푸시하면 반영된다.
  - 서버 운영이 없다. Docker, K8s, CI/CD는 이 규모에 맞지 않아 제외했다. (기획 9장)
- **결과와 제약**
  - 배포 대상 폴더는 `vocab-quiz/`이다. GitHub Pages 설정에서 해당 폴더를 지정한다.
  - 배포 설정 방법은 형상/배포관리 정의서에 적는다.

## ADR-004: 재출제 간격은 문제 수 기준 8~12

- **상태**: 승인 대기 (2026-11-18 초안, 기존 코드 규칙을 기록)
- **배경**: 틀린 단어를 바로 다시 내면 암기에 도움이 되지 않고, 너무 늦게 내면 잊는다. 간격을 정해야 한다. (기획 4.3)
- **대안**
  1. 시간 기준 간격 (예: 10분, 1일 뒤) — 간격 반복 학습(SRS) 방식
  2. 문제 수 기준 고정 간격 (예: 항상 8)
  3. 문제 수 기준 최소 8 + 무작위 0~4 (선택)
  4. 문제 수 기준 3~7 (앞선 답변에서 검토했다가 대체됨)
- **결정 근거**
  - 세션 안에서 바로 다시 나오면 기억에 의존하게 되므로, 최소 8문제 간격을 둔다.
  - 무작위 추가 간격은 같은 순서로 반복되는 것을 막는다.
  - 시간 기준은 사용자가 앱을 열지 않으면 출제되지 않아 세션 설계와 맞지 않는다.
- **결과와 제약**
  - 3~7 규칙은 사용하지 않는다. (2026-11-18 결정)
  - 간격을 못 채우는 경우(신규가 모두 나간 뒤)는 FR-17로 처리한다.

## ADR-005: 오답 선택지는 뜻을 공유하지 않는 단어에서만 고른다

- **상태**: 승인 대기 (2026-11-18 초안, 이미 코드 반영됨 `e4bc27e`)
- **배경**: 뜻이 겹치는 단어 10쌍이 있다. (예: alter·modify '변경하다') 오답 선택지에 정답과 같은 뜻이 나오면 정답이 둘이 되어 정당하게 맞힌 답이 틀린 것으로 처리된다.
- **대안**
  1. 단어 데이터의 뜻을 목록으로 분리하고, 목록끼리 비교 (데이터 구조 변경)
  2. 데이터에서 겹치는 단어를 수작업으로 삭제 (단어 수 감소)
  3. 출제 시 쉼표 뜻 조각을 비교해 겹치는 오답 제외 (선택)
- **결정 근거**
  - 데이터 구조와 단어 64개를 그대로 유지할 수 있다.
  - 뜻 목록 분리는 객관식에서 필요하지 않다. 여러 뜻 판정은 정답 선택지 번호로 충분하다.
  - 검증 단계에서 오답 후보가 부족하면 오류로 알려 준다.
- **결과와 제약**
  - 뜻이 겹치는 단어끼리는 같은 문제에 나오지 않는다. 대신 다른 단어 수가 충분해야 한다. (검증 규칙으로 보장)
  - 뜻 조각 비교는 단순 문자열 일치다. 같은 뜻을 다른 말로 적으면 잡히지 않는다. 필요하면 데이터에서 표기를 맞춘다.
